## 1. Author verification

**Source of author records.** All author names and identities come from OpenAlex
`works` records (`authorships[]`: `author.id`, `author.display_name`,
`raw_author_name`, `author_position`, `institutions[]`, `affiliations[]`). They are
fetched by `part1_collect_data.py` and compacted by `group10_common.compact_work`.
No other source of author identity is used.

**What is verified, and how.**

| Check | How | Where |
|---|---|---|
| The author belongs to one of the three institutes on that paper | The authorship lists the institute's OpenAlex institution ID (`I26072440`, `I9747756`, `I181514455`; checked against ROR `03rgjt374`, `008b3ap06`, `05h9eqy10`). Raw affiliation strings are kept for department parsing. | `part1b_enrich_data.affiliated_authorships` |
| Two records are the same person | Rules in section 2 (OpenAlex ID first, then co-author evidence) | `part1b_enrich_data.resolve_author_identities` |
| Mega-collaborations do not hide authors | OpenAlex returns at most 100 authorships per work; such works keep the institute through the query that returned them (`found_via`) | `group10_common.our_institutions_on` |
| Publication metadata | DOI normalisation; versions of the same paper (preprint / repository / published) are merged by normalised title + at least one shared author name, or by identical DOI | `group10_common.select_corpus` |

**What is NOT verified (gap).** No external authority was used. Author identities
were **not** cross-checked against ORCID, institute faculty pages, IRINS, Scopus
author IDs or CVs. ORCID iDs are present in OpenAlex but are not stored in the
compact cache. "Core faculty" is a heuristic (≥5 papers in ≥3 years, last author on
≥30% and first author on ≤50%), not an official faculty list.

**Proposed procedure (not implemented).**
1. Store `authorships[].author.orcid` in the cache (requires re-downloading `works`).
2. For core faculty and every bridge author (about 160 people): match the OpenAlex
   profile to the institute's faculty page and, where present, ORCID. Record the
   evidence (URL, date checked) in a reviewed CSV.
3. Treat two OpenAlex IDs that share an ORCID as one person. Never merge IDs whose
   ORCIDs differ.
4. Re-run the pipeline and report how centrality, bridges and node cuts change.

## 2. Authors with identical names

**Risks.**
* *False merge* (two people become one node). Common Indian names make this a
  real risk. In this data, 11 different OpenAlex IDs named "Amit Kumar" appear at
  IIITA and ABV. Merging them invents a hub and **creates false bridges between
  institutes**.
* *False split* (one person becomes several nodes). This happens with spelling
  variants ("Boddepalli Santhi Bhushan" / "Boddepalli SanthiBhushan"), initials,
  missing OpenAlex IDs, or OpenAlex splitting one profile. It lowers degree,
  breaks paths and can hide a bridge.

**Policy (implemented, `resolve_author_identities`).** The OpenAlex author ID is
the unit of identity. OpenAlex's own disambiguation, which uses co-authors,
institutions, topics and ORCID, is the strongest evidence available offline.
Two records are merged only if **all** of these hold:

1. identical normalised name (lower case, punctuation removed) with **≥ 2 tokens**;
2. both have papers at the **same** assigned institute;
3. they **never appear on the same paper** (two authorships on one paper are two people);
4. they share **at least one OpenAlex co-author ID** across their papers.

A matching name alone is never enough. Merges are never made across institutes.
An OpenAlex ID that OpenAlex itself places at two of the institutes stays one
person, because it may be a real move or dual affiliation (see section 4). An
authorship without any OpenAlex ID gets a per-paper pseudo ID
(`noid:<work>:<name>`). It joins another record only under the same four rules;
otherwise it stays a separate node.

**Outcome (current run).** 4,643 raw records (OpenAlex IDs plus per-paper pseudo
IDs) resolve to 4,041 authors: 602 merges backed by co-author evidence, and 1,268
same-name records kept separate. The reasons are: same name but no shared
co-author, co-occurrence on a paper, or single-token names such as "Sunny" or
"Abhishek". Same-paper conflicts after resolution: 0. Every decision is written to
`outputs/group10_author_identity_audit.csv` for manual review. That file is
private because it contains names.

**Why the earlier rule was replaced.** The original pipeline merged all IDs with
identical normalised names. That folded 741 IDs into 295 "people", including 5
cases where two same-name people on the **same paper** became one node, and 72
merged nodes spanning two institutes. `part5b_network_structure.identity_sensitivity`
rebuilds the graph with name-only identities so the effect is measured:

| | Name-only (old) | Conservative (current) |
|---|---|---|
| Authors | 3,727 | 4,041 |
| Links between authors of different institutes | 264 | 138 |
| Institute assortativity | 0.949 | 0.974 |
| Giant-component path length (sampled) | 5.47 | 6.14 |

**Impact of residual ambiguity.**
* *Nodes/edges:* remaining false splits lower degree and strength of prolific
  authors with spelling variants. Remaining false merges can only come from
  OpenAlex profiles that already combine two people; our rules add none without
  co-author evidence.
* *Centrality:* split authors lose betweenness; a missed merge of a real bridge
  author would understate inter-institute connectivity.
* *Communities:* Louvain is stable across seeds (pairwise NMI 0.93–0.95), so small
  identity errors move individual nodes rather than redrawing communities.
* *Institution-level findings:* the conservative rule can only *under*-state
  inter-institute ties relative to the truth from false splits; it cannot invent
  them. The "three islands" conclusion is therefore conservative-safe. The exact
  node-cut sizes (8 and 28) are the most sensitive numbers.

**Manual review needed.** Bridge authors and the IIITB node cut (8 people), and
any audit rows marked "kept separate" for core faculty with name variants.

## 3. End-to-end data processing pipeline

Execution order: `part1_collect_data.py` → `part1b_enrich_data.py` →
`part2_networks.py` → `part3_statistics.py` → `part5_insights.py` →
`part5b_network_structure.py` → `part4_dashboard.py` → `part6_report.py`.
Shared code: `group10_common.py` (configuration, OpenAlex client, classification
rules) and `group10_analysis.py` (loading and statistics used by every output).

| # | Stage | What happens / why | Code | In → out | Errors, missing values, duplicates | Validation |
|---|---|---|---|---|---|---|
| 1 | Ingestion | Download all works 2016–2026 for the three OpenAlex institution IDs, plus Indian works citing / cited by them (batched `cites:` / `cited_by:` filters + `country_code:IN`) | `part1_collect_data.py` | OpenAlex API → `cache/*.json.gz` | Retries, rate-limit and daily-budget handling; resumable; works with >100 authors re-queried by institution | Counts per institute printed; cache is the single raw source |
| 2 | Schema & field selection | Keep only the fields used later (IDs, DOI, year, type, venue locations, authorships with raw affiliations, references, topics, citations, retraction, OA) | `group10_common.compact_work` | raw JSON → compact records | Missing values become empty strings / 0 | — |
| 3 | Inclusion & cleaning | Keep journal and conference papers 2016–2026 with an affiliated author; drop preprints, book chapters, errata, editorials, datasets, peer reviews, retracted works | `classify_work`, `select_corpus` | works → corpus | Unknown venue: conference papers kept, others dropped with a reason | Exclusion counts by reason printed |
| 4 | Deduplication | Merge versions of one paper (same normalised title ≥25 chars + shared author name, or same DOI); citations = max over versions; references to an alias are credited to the canonical paper | `select_corpus`, `effective_citations` | corpus → canonical papers + alias map | Preference: journal > conference, named venue, more citations | "duplicate version" count printed |
| 5 | Venue quality | Scimago quartile of the journal **in the publication year** (±2 years fallback; 2026 → 2025); conferences: strict ICORE2026 match | `Scimago`, `CoreRanks` | venue + year → quartile / rank | Unranked → empty | Workshops never inherit main-track rank |
| 6 | Author identity | Section 2 | `resolve_author_identities` | authorships → canonical author IDs | Conflicts kept separate; audit CSV | 0 same-paper conflicts |
| 7 | Three institutes | Each paper gets one row per assigned institute in `group10_data.csv`; each author's *main* institute = where most of their papers are; authors placed at two institutes are flagged | `build_dataset`, `part2_networks.build_authorship` | corpus → dataset rows | Papers shared by two institutes appear twice; use `openalex_id` to deduplicate | 38 papers carry two institutes, none carry all three |
| 8 | Nodes & edges | Citation: paper → paper if A references B (directed, unweighted, self-loops removed). Co-authorship: author–author if they share a paper (undirected, weight = joint papers). Cross-institute edges to other Indian institutes are written to the CSVs only | `part2_networks.py` | dataset + cache → `citation_network.csv`, `authorship_network.csv`, `indian_connections.csv` | Papers with >50 authors add no external edges | Edge-type counts printed |
| 9 | Network metrics | PageRank, in-degree, degree/betweenness, Louvain; inferential tests; structure and inter-institution analysis | `part2`, `part5_insights.py`, `part5b_network_structure.py` | networks → `outputs/*.json` | Disconnected graphs: path metrics on giant component | Null models, seed stability, sensitivity analysis |
| 10 | Derived outputs | Report figures, statistics summary, dashboard data | `part3`, `part5`, `part5b`, `part4`, `part6` | JSON/CSV → PNG, PDF, HTML | Missing inputs → empty-state messages | Dashboard and report read the same JSON |
| 11 | Dashboard & deployment | One self-contained HTML (D3 + Chart.js inlined) written to `dashboard.html` and `site/index.html`; deployed by uploading `site/` to Netlify (<https://cozy-kitsune-3c4e7e.netlify.app/>) | `part4_dashboard.py`, `netlify.toml` | JSON → HTML | Global error banner; empty tables say so | Headless-browser render of every page with no JS errors |

## 4. Key methodological decisions and trade-offs

| Decision | Rationale | Alternatives considered | Implication |
|---|---|---|---|
| **Node = author** (co-authorship), **node = paper** (citation) | Required by the course note; directly observable in OpenAlex | Institution-level graph | Institution-level ties are aggregated from author ties (mixing matrix) |
| **Edge = co-authored ≥1 paper**; weight = joint papers | Observable fact; no claim about informal collaboration | Fractional (1/(n−1)) weights | Large teams create cliques → high clustering by construction |
| **Undirected, weighted** co-authorship; **directed, unweighted** citation | Natural semantics | — | Path metrics reported only for the co-authorship giant component; the citation graph is almost acyclic with 3,355 weak components |
| Author's **main institute** = most papers | One colour/group per node is needed for mixing and node cuts | Multi-membership nodes | 35 authors placed at two institutes are flagged and analysed separately |
| Isolated authors and small components **kept** | They are real (single-author or external-only collaboration) | Drop | Density and giant share are reported for the full graph; paths on the giant component |
| **Louvain** (seed 42) + stability over 10 seeds | Standard for weighted modular graphs; NMI 0.93–0.95 across seeds | Leiden (proposed; not needed given stability) | Communities are co-writing clusters, not departments (NMI with department 0.43) |
| **Centralities:** degree, betweenness (exact), closeness, eigenvector | Each answers a different question | — | Eigenvector localises on IIITA (99% of squared mass) → not used to compare institutes |
| **Baselines:** ER G(n, m); configuration model for modularity and inter-institute links; target-shuffled citation graphs | ER tests "is it random?"; configuration model controls for hubs; shuffling controls for citation volume | — | Departures from these baselines show non-randomness, not causes |
| Robustness by **static** betweenness order | Simple, interpretable | Adaptive recomputation | Slightly understates fragility; a thought experiment |
| Excluding **>50-author** papers from external edges and normalised impact | One 100+ author paper would dominate | Fractional counting | Documented in dashboard and report |

**Known biases.** OpenAlex coverage is weaker before 2018 and for Indian
conference proceedings. IIITB authors rarely state a department, so departments
there are mostly inferred. Citation counts depend on paper age, so 2025–26 papers
are excluded from normalised scores.

## 5. Reproducibility and privacy

**Getting the data (authorised users).** The dataset is OpenAlex-derived and is
shared only with the course instructor. An authorised user can either:
* copy the private `cache/` folder (raw OpenAlex responses) into the project root
  and run steps 1b–6 offline, or
* rebuild it from OpenAlex with `python part1_collect_data.py`. This needs roughly
  600 requests; the scripts resume if the daily budget runs out. An optional
  `OPENALEX_API_KEY` raises the budget.

**Configuration.** Environment variables are listed in `.env.example`:
`OPENALEX_API_KEY`, `OPENALEX_MAILTO`, `OPENALEX_BUDGET_RESERVE` and
`DASHBOARD_URL`. None is required for an offline rebuild.

**Regenerate everything.**
```bash
python -m venv .venv && .venv/Scripts/activate    # Windows; use bin/activate elsewhere
pip install -r requirements.txt
python part1b_enrich_data.py && python part2_networks.py && python part3_statistics.py
python part5_insights.py && python part5b_network_structure.py
python part4_dashboard.py && python part6_report.py
```

**Public vs private.**

| Public (in git) | Private (gitignored, local only) |
|---|---|
| All source code, `requirements.txt`, `netlify.toml`, `.env.example` | `group10_data.csv`, `citation_network.csv`, `authorship_network.csv`, `indian_connections.csv` |
| `README.md`, `DECISIONS.md`, course documents in `docs/` | `cache/` (raw OpenAlex responses) |
| Report `10_IIIT.pdf` and aggregate figures in `outputs/charts/` | `outputs/*.csv`, `outputs/*.json`, `outputs/*.md` (author-level records, identity audit) |
| Dashboard screenshots in `docs/images/` (no tables of individuals) | `dashboard.html`, `site/` (the built dashboard embeds author names and paper records) |
| Reference tables in `reference/` (Scimago SJR, ICORE ranks; public sources) | `.env`, `outputs/charts/f4_*.png`, `outputs/charts/11_*.png` (legends name individuals) |

The `.gitignore` rules enforce this split.

**History caveat.** In the initial commit (`4a161f4`) the dataset, network CSVs, cache and
`dashboard.html` were committed and pushed to GitHub. Removing them from
tracking does **not** remove them from Git history. Purging them requires rewriting
history (`git filter-repo`) and force-pushing, which has not been done and needs
the repository owner's decision.

**Note on the public dashboard.** The deployed dashboard necessarily shows the
author names and paper titles behind its networks, as the course requires. These
are public bibliographic facts from OpenAlex, but publishing the page does make
them visible. The raw dataset files themselves are not published.
